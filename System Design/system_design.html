🏗 Mobile System Design — Interview

Google expects you to design complete mobile systems. Use this framework for every question. Practice these 6 designs until you can do each in 45 minutes.

The Framework

★Framework for ANY mobile system design questionMust Know
  1. Clarify requirements (5 min): Functional (what features?), Non-functional (scale, offline, latency), Platform (Android only? iOS too?)
  2. High-level architecture (5 min): Layers — Presentation, Domain, Data. Draw the box diagram.
  3. Data models (5 min): What entities? What does the local DB store? What does the API return?
  4. API design (5 min): What endpoints does the app call? Request/response shapes.
  5. Key screens + navigation (5 min): Main screens, navigation graph, what's cached.
  6. Networking strategy (10 min): Pagination, caching strategy, offline behavior, sync.
  7. Performance + optimization (5 min): Image loading, lazy loading, prefetching, memory.
  8. Edge cases (5 min): No network, partial data, large lists, expired cache.

Design: Instagram Feed

D1Design Instagram-style infinite scroll feed for AndroidHard

Requirements: Infinite scroll, images, likes/comments, offline support, smooth 60fps scroll

Architecture:

// Data model
@Entity
data class Post(
    @PrimaryKey val id: String,
    val userId: String,
    val imageUrl: String,
    val caption: String,
    val likesCount: Int,
    val createdAt: Long,
    val page: Int  // for invalidation
)

// Paging 3 — handles pagination, loading states, errors
class FeedPagingSource(
    private val api: FeedApi
) : PagingSource<String, Post>() { // key=cursor, value=Post
    override suspend fun load(params: LoadParams<String>): LoadResult<String, Post> {
        return try {
            val response = api.getFeed(cursor = params.key, limit = params.loadSize)
            LoadResult.Page(
                data = response.posts,
                prevKey = null,           // no back-paging in feed
                nextKey = response.nextCursor
            )
        } catch (e: Exception) { LoadResult.Error(e) }
    }
}

// RemoteMediator for offline-first (network + Room)
@OptIn(ExperimentalPagingApi::class)
class FeedRemoteMediator(
    private val api: FeedApi,
    private val db: AppDatabase
) : RemoteMediator<Int, Post>() {
    override suspend fun load(loadType: LoadType, state: PagingState<Int, Post>): MediatorResult {
        val posts = api.getFeed(/* ... */)
        db.withTransaction {
            if (loadType == LoadType.REFRESH) db.postDao().clearAll()
            db.postDao().insertAll(posts)
        }
        return MediatorResult.Success(endOfPaginationReached = posts.isEmpty())
    }
}

Image loading strategy:

  • Use Coil: memory cache (LRU, ~25% heap) + disk cache + placeholder + crossfade
  • Pre-fetch next 3 images while user scrolls using CoilPrefetcher
  • Different quality for scroll vs stopped (low-res thumbnail → full res)
  • Cancel image loads for off-screen items via ImageRequest lifecycle

Performance optimizations:

  • DiffUtil with stable IDs — only rebind changed items
  • RecycledViewPool shared across multiple RecyclerViews
  • ViewHolder caching: setRecycledViewPool, setItemViewCacheSize
  • Avoid nested RecyclerViews — use ConcatAdapter instead

Design: Chat Application

D2Design a WhatsApp-style chat appHard

Key challenges: Real-time messages, delivery receipts, offline queue, message ordering

// Message data model
@Entity
data class Message(
    @PrimaryKey val id: String,
    val chatId: String,
    val senderId: String,
    val content: String,
    val type: MessageType, // TEXT, IMAGE, AUDIO
    val status: MessageStatus, // PENDING, SENT, DELIVERED, READ
    val timestamp: Long,
    val localId: String // client-generated before server confirms
)

// Optimistic UI: show message as PENDING immediately, update on server ACK
fun sendMessage(text: String) {
    val localMessage = Message(localId = UUID.randomUUID(), status = PENDING)
    db.messageDao().insert(localMessage) // show immediately in UI
    viewModelScope.launch(Dispatchers.IO) {
        try {
            val serverMsg = api.sendMessage(text)
            db.messageDao().update(serverMsg.copy(status = SENT))
        } catch (e: Exception) {
            db.messageDao().update(localMessage.copy(status = FAILED))
            outbox.add(localMessage) // retry queue
        }
    }
}

Real-time transport options:

  • WebSocket: Persistent connection, truly real-time. Battery cost.
  • FCM: Google's push — app doesn't need to be open. Use for offline messages.
  • Long polling: Simpler but inefficient. Avoid.
  • SSE: Server-sent events — server to client only. Good for notifications.

Recommended: FCM for wakeup + WebSocket when app is foreground. Foreground Service keeps WebSocket alive while app is in background during active chat.

Message sync: On reconnect, fetch all messages with timestamp > last_received_at. Use Room as single source of truth. UI observes Room, not network directly.

Design: Image Loading Library

D3Design an image loading library (like Coil/Glide) from scratchHard — Google Favorite

This is a classic Google interview question. They want to see you think in layers.

// Architecture: 3-level cache + request deduplication
class ImageLoader(context: Context) {

    // L1: Memory cache (LRU, ~25% of available heap)
    private val memoryCache = LruCache<String, Bitmap>(
        (Runtime.getRuntime().maxMemory() / 1024 / 4).toInt()
    )

    // L2: Disk cache (DiskLruCache, ~250MB)
    private val diskCache: DiskLruCache = DiskLruCache.open(cacheDir, 1, 1, 250L*1024*1024)

    // L3: Network (OkHttp with HTTP cache headers)
    private val httpClient: OkHttpClient = OkHttpClient.Builder()
        .cache(Cache(cacheDir, 50L * 1024 * 1024))
        .build()

    // Deduplication: if same URL loading, return same Deferred
    private val inFlight = ConcurrentHashMap<String, Deferred<Bitmap>>()

    suspend fun load(url: String): Bitmap {
        // 1. Check memory cache (main thread ok, fast)
        memoryCache.get(url)?.let { return it }

        // 2. Deduplicate in-flight requests
        return inFlight.getOrPut(url) {
            async(Dispatchers.IO) {
                // 3. Check disk cache
                diskCache.get(url)?.let {
                    val bmp = BitmapFactory.decodeStream(it)
                    memoryCache.put(url, bmp); bmp
                } ?:
                // 4. Fetch from network
                fetchFromNetwork(url).also {
                    diskCache.put(url, it); memoryCache.put(url, it)
                }
            }
        }.await().also { inFlight.remove(url) }
    }
}

Additional considerations Google will ask about:

  • Bitmap pool: Reuse existing Bitmap memory with inBitmap option
  • Downsampling: Never decode full-res if target view is 100x100 — use inSampleSize
  • Transformation pipeline: Crop, circle, blur as post-processing steps
  • Placeholder/error: Show while loading, show on error
  • Cancellation: Cancel request when view is recycled or detached
  • GIF/animated images: Separate decode pipeline

Design: Offline-First App

D4Design an offline-first architecture for a news reading appHard 
// Single source of truth: Room is the only source UI observes
// Network → Room → UI. Never Network → UI directly.

class NewsRepository(
    private val api: NewsApi,
    private val dao: NewsDao,
    private val networkMonitor: NetworkMonitor
) {
    // UI observes this Flow — always gets Room data
    fun getArticles(): Flow<List<Article>> = dao.getArticlesFlow()

    // Refresh called separately — fetches from network and stores in Room
    suspend fun refresh() {
        if (!networkMonitor.isOnline) return // fail silently, show cached
        val articles = api.getLatestArticles()
        dao.insertAll(articles)
        dao.deleteOlderThan(System.currentTimeMillis() - 7 * 24 * 60 * 60 * 1000L)
    }
}

// Network status monitoring
class NetworkMonitor(context: Context) {
    val isOnline: StateFlow<Boolean> = callbackFlow {
        val cm = context.getSystemService(ConnectivityManager::class.java)
        val callback = object : NetworkCallback() {
            override fun onAvailable(network: Network) = trySend(true)
            override fun onLost(network: Network) = trySend(false)
        }
        cm.registerDefaultNetworkCallback(callback)
        awaitClose { cm.unregisterNetworkCallback(callback) }
    }.stateIn(scope, SharingStarted.Eagerly, true)
}

Cache invalidation strategies:

  • Time-based: Delete articles older than N days
  • Size-based: Keep only latest N articles
  • Pull-to-refresh: User-initiated refresh
  • WorkManager: Periodic background refresh when on WiFi + charging
