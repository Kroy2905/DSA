Pattern 1: Two Pointers

P1-1Two Sum — Find pair that sums to targetEasy

The brute-force way checks every pair of numbers, which costs O(n²) time since for each element you rescan the rest of the array looking for its complement. The key insight is that you don't need to search for the complement at all — you can remember every value you've already seen in a hash map as you go, so checking whether the current element's complement showed up earlier becomes an O(1) lookup instead of a scan. That turns the whole problem into a single pass: O(n) time and O(n) space for the map.

// O(n) time, O(n) space — HashMap solution
fun twoSum(nums: IntArray, target: Int): IntArray {
    val seen = HashMap<Int, Int>() // value → index
    for (i in nums.indices) {
        val complement = target - nums[i]
        if (seen.containsKey(complement)) {
            return intArrayOf(seen[complement]!!, i)
        }
        seen[nums[i]] = i
    }
    return intArrayOf()
}
// Key insight: complement = target - current. Check if complement seen before.
P1-2Container With Most Water (Two Pointers)Medium

Checking every pair of lines for the largest container is O(n²). The two-pointer trick instead starts with the widest possible container — one pointer at each end — and shrinks the window inward, always moving the pointer at the shorter line. That's safe because the shorter line is the bottleneck limiting the area; keeping it and narrowing the width can only ever produce an equal or smaller area, so there's never a reason to move the taller pointer instead. Since each pointer only ever moves inward, the whole scan touches each index once: O(n) time, O(1) space.

// Greedy two-pointer: move the shorter side inward
fun maxArea(height: IntArray): Int {
    var left = 0; var right = height.size - 1; var maxWater = 0
    while (left < right) {
        val water = minOf(height[left], height[right]) * (right - left)
        maxWater = maxOf(maxWater, water)
        if (height[left] < height[right]) left++ else right--
        // Move the shorter side — the taller side can't improve by moving
    }
    return maxWater
}
// O(n) time, O(1) space

Pattern 2: Sliding Window

P2-1Longest Substring Without Repeating CharactersMedium

Checking every substring for duplicate characters is O(n³)-ish and wasteful. Instead, maintain a sliding window [left, right] that is always duplicate-free: as right expands one character at a time, a hash map remembers the last index each character was seen at, and the moment a repeat shows up, left jumps directly past that earlier occurrence instead of creeping forward one step at a time. Because both pointers only ever move forward across the string, the whole scan is O(n) time and O(min(n, charset size)) space for the map.

fun lengthOfLongestSubstring(s: String): Int {
    val lastSeen = HashMap<Char, Int>() // char → last index seen
    var left = 0; var maxLen = 0
    for (right in s.indices) {
        if (lastSeen.containsKey(s[right])) {
            // Shrink window past the duplicate
            left = maxOf(left, lastSeen[s[right]]!! + 1)
        }
        lastSeen[s[right]] = right
        maxLen = maxOf(maxLen, right - left + 1)
    }
    return maxLen
}
// O(n) time, O(min(n,m)) space where m = charset size
P2-2Minimum Window SubstringHard

Trying every substring of s and checking whether it contains all of t's characters is far too slow. This is a variable-size sliding window instead: expand right to pull characters into the window, and track how many of t's required character counts are currently satisfied with a formed counter — once formed == need.size, the window is a valid candidate. From there, greedily shrink from left for as long as the window stays valid, recording the smallest valid window seen, since a smaller valid window is always at least as good as a larger one covering the same required characters. Each pointer only ever moves forward through the string, so despite the nested loops this runs in O(|s| + |t|) time and O(|s| + |t|) space for the two count maps.

fun minWindow(s: String, t: String): String {
    if (s.isEmpty() || t.isEmpty()) return ""
    val need = HashMap<Char, Int>()
    for (c in t) need[c] = (need[c] ?: 0) + 1
    var left = 0; var formed = 0; val window = HashMap<Char, Int>()
    var minLen = Int.MAX_VALUE; var minLeft = 0
    for (right in s.indices) {
        window[s[right]] = (window[s[right]] ?: 0) + 1
        if (need.containsKey(s[right]) && window[s[right]] == need[s[right]]) formed++
        while (formed == need.size) { // window is valid, try to shrink
            if (right - left + 1 < minLen) { minLen = right - left + 1; minLeft = left }
            window[s[left]] = window[s[left]]!! - 1
            if (need.containsKey(s[left]) && window[s[left]]!! < need[s[left]]!!) formed--
            left++
        }
    }
    return if (minLen == Int.MAX_VALUE) "" else s.substring(minLeft, minLeft + minLen)
}

Pattern 3: Binary Search

P3-1Classic binary search template — know this coldEasy

Binary search works because comparing the target to the middle element of a sorted array eliminates half the remaining search space on every step — the target either equals the middle, or it must live entirely in the left half, or entirely in the right half. Repeating that halving means at most log₂(n) comparisons are ever needed, giving O(log n) time and O(1) space instead of the O(n) a linear scan would take. The exact-match template returns as soon as it finds the target, while the lower-bound template narrows the range down to the single leftmost index where the target could be inserted without breaking sort order — that variant is the pattern behind "first occurrence" and "insertion point" style questions.

// Template: find exact target
fun binarySearch(nums: IntArray, target: Int): Int {
    var lo = 0; var hi = nums.size - 1
    while (lo <= hi) {
        val mid = lo + (hi - lo) / 2 // avoid overflow
        when {
            nums[mid] == target -> return mid
            nums[mid] < target -> lo = mid + 1
            else -> hi = mid - 1
        }
    }
    return -1
}

// Template: find leftmost position (first occurrence)
fun lowerBound(nums: IntArray, target: Int): Int {
    var lo = 0; var hi = nums.size // hi = size (not size-1)
    while (lo < hi) { // strict less (not <=)
        val mid = lo + (hi - lo) / 2
        if (nums[mid] < target) lo = mid + 1 else hi = mid
    }
    return lo // first position where nums[pos] >= target
}
P3-2Search in Rotated Sorted ArrayMedium — Google Favorite

A rotated sorted array isn't fully sorted end to end, so plain binary search doesn't directly apply — but the key insight is that at any midpoint, at least one of the two halves is still guaranteed to be normally sorted. So at each step, first figure out which half is sorted by comparing nums[lo] to nums[mid], then check whether the target falls inside that sorted half's value range. If it does, recurse into that half; if not, the target must be in the other (rotated) half, so recurse there instead. This still halves the search space every iteration, preserving the O(log n) time and O(1) space of standard binary search despite the rotation.

fun search(nums: IntArray, target: Int): Int {
    var lo = 0; var hi = nums.size - 1
    while (lo <= hi) {
        val mid = lo + (hi - lo) / 2
        if (nums[mid] == target) return mid
        // Determine which half is sorted
        if (nums[lo] <= nums[mid]) { // left half is sorted
            if (target >= nums[lo] && target < nums[mid]) hi = mid - 1
            else lo = mid + 1
        } else { // right half is sorted
            if (target > nums[mid] && target <= nums[hi]) lo = mid + 1
            else hi = mid - 1
        }
    }
    return -1
}
// Key insight: at least one half is always sorted. Check which half, then decide.

Pattern 4: Trees

P4-1BFS and DFS templates for treesEasy

DFS and BFS are the two fundamental ways to visit every node of a tree, and which one to reach for depends on what you need out of the traversal. DFS recurses depth-first — for inorder that means fully exploring the left subtree, visiting the root, then the right subtree — which is why inorder traversal of a BST naturally comes out in sorted order. BFS instead uses a queue to process the tree level by level, which is the only traversal that naturally groups nodes by depth (useful for "level order" or "minimum depth" style questions). Both visit every node exactly once, so each is O(n) time; DFS uses O(h) space for the recursion stack (h = tree height) while BFS uses O(w) space for the queue (w = the tree's maximum width).

class TreeNode(var value: Int, var left: TreeNode? = null, var right: TreeNode? = null)

// DFS: inorder (left-root-right) — gives sorted order for BST
fun inorder(root: TreeNode?, result: MutableList<Int>) {
    if (root == null) return
    inorder(root.left, result)
    result.add(root.value)
    inorder(root.right, result)
}

// BFS: level order traversal
fun levelOrder(root: TreeNode?): List<List<Int>> {
    if (root == null) return emptyList()
    val result = mutableListOf<List<Int>>()
    val queue: ArrayDeque<TreeNode> = ArrayDeque()
    queue.addLast(root)
    while (queue.isNotEmpty()) {
        val levelSize = queue.size
        val level = mutableListOf<Int>()
        repeat(levelSize) {
            val node = queue.removeFirst()
            level.add(node.value)
            node.left?.let { queue.addLast(it) }
            node.right?.let { queue.addLast(it) }
        }
        result.add(level)
    }
    return result
}
P4-2Lowest Common Ancestor of Binary TreeMedium — Google Favorite

The recursive approach searches both subtrees for p and q at the same time: at each node, recurse into the left and right children looking for either target. If both the left and right recursive calls come back non-null, that means p and q were found in different subtrees — which means the current node is exactly where their paths to the root diverge, making it the lowest common ancestor. If only one side is non-null, that result is simply passed up unchanged, since the LCA (or one of the targets itself) must live entirely within that subtree. Each node is visited once, so this is O(n) time and O(h) space for the recursion stack.

fun lowestCommonAncestor(root: TreeNode?, p: TreeNode?, q: TreeNode?): TreeNode? {
    if (root == null || root == p || root == q) return root
    val left = lowestCommonAncestor(root.left, p, q)
    val right = lowestCommonAncestor(root.right, p, q)
    // If found in both subtrees, root is LCA
    if (left != null && right != null) return root
    return left ?: right
}
// O(n) time — visits each node once. Key: if both subtrees return non-null, root is LCA

Pattern 5: Dynamic Programming

P5-1Climbing Stairs — DP foundationEasy

Climbing Stairs is really Fibonacci in disguise: to reach step n, the last move taken was either a single step from step n-1 or a double step from step n-2, so the total number of ways to reach n is simply the sum of the ways to reach those two prior steps. A naive recursive implementation of that recurrence would recompute the same subproblems exponentially many times, so instead the solution builds up from the base cases iteratively, keeping only the last two computed values. That reduces it to a single forward pass: O(n) time and O(1) space, since only two rolling variables are needed instead of a full DP array.

// Recurrence: ways(n) = ways(n-1) + ways(n-2)
// O(n) time, O(1) space — rolling variables
fun climbStairs(n: Int): Int {
    if (n <= 2) return n
    var prev2 = 1; var prev1 = 2
    for (i in 3..n) {
        val cur = prev1 + prev2
        prev2 = prev1; prev1 = cur
    }
    return prev1
}
P5-2Longest Common SubsequenceMedium

Trying every subsequence of one string against every subsequence of the other is exponential and completely impractical. Instead, build a 2D table where dp[i][j] represents the LCS length of the first i characters of text1 and the first j characters of text2: if those two characters match, they extend the best subsequence found without them by one; if they don't match, the best is whichever of dropping the last character of text1 or of text2 leaves the longer subsequence. Filling this table bottom-up reuses previously solved subproblems instead of recomputing them — the whole point of dynamic programming — giving O(m·n) time and O(m·n) space for the table.

fun longestCommonSubsequence(text1: String, text2: String): Int {
    val m = text1.length; val n = text2.length
    val dp = Array(m + 1) { IntArray(n + 1) } // dp[i][j] = LCS of text1[0..i-1] and text2[0..j-1]
    for (i in 1..m) {
        for (j in 1..n) {
            dp[i][j] = if (text1[i-1] == text2[j-1]) dp[i-1][j-1] + 1
                       else maxOf(dp[i-1][j], dp[i][j-1])
        }
    }
    return dp[m][n]
}
// O(m*n) time and space. Classic 2D DP problem.

Pattern 6: Graph BFS/DFS

P6-1Number of Islands — DFS on gridMedium — Must Know

Every time the scan hits an unvisited land cell ('1'), it must be the start of a brand-new island — so the island count is incremented and a DFS floods outward from that cell, marking every connected land cell as visited (by flipping it to '0') so it's never counted again. This is the standard "flood fill" pattern for counting connected components on a grid. Each cell is visited a constant number of times overall, so the scan plus all the flood fills together run in O(rows × cols) time, and mutating the grid in place to mark visited cells avoids the O(rows × cols) space a separate visited set would cost.

fun numIslands(grid: Array<CharArray>): Int {
    var count = 0
    for (r in grid.indices) {
        for (c in grid[r].indices) {
            if (grid[r][c] == '1') {
                count++
                dfs(grid, r, c) // mark all connected land as visited
            }
        }
    }
    return count
}

private fun dfs(grid: Array<CharArray>, r: Int, c: Int) {
    if (r < 0 || r >= grid.size || c < 0 || c >= grid[0].size || grid[r][c] != '1') return
    grid[r][c] = '0' // mark visited
    dfs(grid, r+1, c); dfs(grid, r-1, c)
    dfs(grid, r, c+1); dfs(grid, r, c-1)
}
// O(m*n) time. Modify grid in-place to avoid visited set.
P6-2Word Ladder — BFS shortest pathHard

This is a shortest-path problem on an implicit graph where each word is a node and an edge connects two words that differ by exactly one letter — and BFS is the right tool precisely because it explores that graph level by level, so the first time the end word is reached is guaranteed to be via the shortest possible sequence of transformations. At each step, every possible one-letter substitution of the current word is generated and checked against the dictionary; removing a word from the set the moment it's used doubles as marking it visited, which prevents revisits and keeps the search from looping. Generating variations costs O(L · 26) per word of length L, so the overall complexity is O(n · L · 26) time with O(n) space for the queue and word set.

fun ladderLength(beginWord: String, endWord: String, wordList: List<String>): Int {
    val wordSet = wordList.toHashSet()
    if (!wordSet.contains(endWord)) return 0
    val queue: ArrayDeque<String> = ArrayDeque()
    queue.addLast(beginWord); var steps = 1
    while (queue.isNotEmpty()) {
        repeat(queue.size) {
            val word = queue.removeFirst()
            for (i in word.indices) {
                for (c in 'a'..'z') {
                    val next = word.substring(0, i) + c + word.substring(i+1)
                    if (next == endWord) return steps + 1
                    if (wordSet.remove(next)) queue.addLast(next)
                }
            }
        }
        steps++
    }
    return 0
}
// BFS guarantees shortest path. Remove from set to mark visited.

Pattern 7: Backtracking

P7-1Subsets — all possible subsets of a setMedium

Backtracking explores a decision tree where at each index you either include or exclude the current element, then recurse on the rest. Because every partial path is itself a valid subset, current is recorded at the top of every call rather than only at a "base case" — together the tree's nodes account for all 2^n subsets.

fun subsets(nums: IntArray): List<List<Int>> {
    val result = mutableListOf<List<Int>>()
    val current = mutableListOf<Int>()
    fun backtrack(start: Int) {
        result.add(current.toList())       // every partial state is a valid subset
        for (i in start until nums.size) {
            current.add(nums[i])              // include
            backtrack(i + 1)
            current.removeAt(current.size - 1) // exclude — undo
        }
    }
    backtrack(0)
    return result
}
// O(n * 2^n) time, O(n) space (recursion depth)
P7-2Permutations — all orderings of a setMedium

Same include/exclude recursion shape as Subsets above, but here order matters and every element must appear exactly once. A used[] array tracks which indices are already placed in the current path — skipping used indices while descending, then un-marking them after the recursive call returns ("undo"), is what lets one array serve every branch. The recursion tree looks just like the Subsets diagram above, except every root-to-leaf path has length n instead of a varying length.

fun permute(nums: IntArray): List<List<Int>> {
    val result = mutableListOf<List<Int>>()
    val path = mutableListOf<Int>()
    val used = BooleanArray(nums.size)
    fun backtrack() {
        if (path.size == nums.size) { result.add(path.toList()); return }
        for (i in nums.indices) {
            if (used[i]) continue
            used[i] = true; path.add(nums[i])
            backtrack()
            path.removeAt(path.size - 1); used[i] = false // undo
        }
    }
    backtrack()
    return result
}
// O(n * n!) time, O(n) space

Pattern 8: Heap / Priority Queue

P8-1Kth Largest Element in an ArrayMedium

Keep a min-heap capped at size k. Push every value; whenever the heap grows past k, pop — that always evicts the current smallest of the k largest-so-far. After scanning all n elements, whatever remains at the root is the kth largest. This beats sorting the whole array (O(n log n)) whenever k is much smaller than n.

fun findKthLargest(nums: IntArray, k: Int): Int {
    val minHeap = PriorityQueue<Int>()
    for (num in nums) {
        minHeap.add(num)
        if (minHeap.size > k) minHeap.poll() // evict smallest, keep size == k
    }
    return minHeap.peek()
}
// O(n log k) time, O(k) space
P8-2Merge K Sorted ListsHard — Google Favorite

Seed a min-heap ordered by node value with the head of each of the k lists. Repeatedly pop the smallest node, append it to the merged output, then push that node's next (if it exists) back into the heap. This is the same k-way merge used inside merge sort — the heap just replaces manually comparing k pointers on every step.

class ListNode(var value: Int, var next: ListNode? = null)

fun mergeKLists(lists: Array<ListNode?>): ListNode? {
    val heap = PriorityQueue<ListNode>(compareBy { it.value })
    for (node in lists) node?.let { heap.add(it) }
    val dummy = ListNode(0); var tail = dummy
    while (heap.isNotEmpty()) {
        val smallest = heap.poll()
        tail.next = smallest; tail = smallest
        smallest.next?.let { heap.add(it) } // push popped list's next node
    }
    return dummy.next
}
// O(n log k) time, O(k) space

Pattern 9: Trie

P9-1Implement Trie (Prefix Tree)Medium

Each TrieNode holds a map from the next character to a child node, plus an isEnd flag. insert walks the word, creating child nodes on demand; search walks the same path and only succeeds if it lands on a node flagged isEnd (startsWith is identical but skips that final check). The diagram below shows the shared structure after inserting "cat", "car" and "dog" — note how "cat" and "car" share the c→a path before splitting.

class TrieNode {
    val children = HashMap<Char, TrieNode>()
    var isEnd = false
}

class Trie {
    private val root = TrieNode()
    fun insert(word: String) {
        var node = root
        for (c in word) node = node.children.getOrPut(c) { TrieNode() }
        node.isEnd = true
    }
    fun search(word: String): Boolean {
        var node = root
        for (c in word) node = node.children[c] ?: return false
        return node.isEnd
    }
}
// insert/search: O(L) time, L = word length
💡 Extension — Word Search II: build one Trie from the whole dictionary, then backtrack over the grid; at each cell, step into node.children[grid[r][c]] and prune immediately if it doesn't exist. Far cheaper than searching the grid once per word.
P9-2Longest Common Prefix (Trie-based)Easy

Insert every string into a Trie, then walk the path spelled by strs[0]. The shared prefix ends the instant a node has more than one child (the strings diverge) or a shorter inserted word ends exactly there (isEnd). In the Trie diagram above, inserting "cat","car","dog" branches at the root immediately (children c and d), so their combined LCP is ""; insert just "cat","car" and the shared path continues through c→a before splitting at t vs r, giving LCP "ca".

fun longestCommonPrefix(strs: Array<String>): String {
    if (strs.isEmpty()) return ""
    val root = TrieNode()
    for (s in strs) {
        var node = root
        for (c in s) node = node.children.getOrPut(c) { TrieNode() }
        node.isEnd = true
    }
    val sb = StringBuilder()
    var node = root
    for (c in strs[0]) {
        if (node.children.size != 1 || node.isEnd) break // branch, or a shorter word ends here
        node = node.children[c]!!; sb.append(c)
    }
    return sb.toString()
}
// O(sum of string lengths) time and space

Pattern 10: Linked List

P10-1Reverse a Linked ListEasy

Walk the list once with three pointers: prev (the already-reversed portion), cur (the node being processed), and a temporary next that saves where to go before you overwrite cur.next. Each iteration flips exactly one link; once cur runs out, prev is sitting on the new head.

class ListNode(var value: Int, var next: ListNode? = null)

fun reverseList(head: ListNode?): ListNode? {
    var prev: ListNode? = null
    var cur = head
    while (cur != null) {
        val next = cur.next   // save before overwriting
        cur.next = prev
        prev = cur; cur = next
    }
    return prev // new head
}
// O(n) time, O(1) space
P10-2Detect Cycle in a Linked ListMedium — Google Favorite

Floyd's Tortoise and Hare: advance slow one step and fast two steps per round. If there's a cycle, fast eventually laps slow and they land on the same node; if fast reaches null first, there's no cycle. To find where the cycle begins: once they meet, reset one pointer to head and advance both one step at a time — they meet again exactly at the cycle's entry point (the distance from head to the entry equals the distance from the meeting point to the entry, modulo the cycle length).

fun hasCycle(head: ListNode?): Boolean {
    var slow = head; var fast = head
    while (fast?.next != null) {
        slow = slow?.next
        fast = fast.next?.next
        if (slow === fast) return true // pointers meet -> cycle
    }
    return false
}
// O(n) time, O(1) space

Pattern 11: Intervals / Greedy

P11-1Merge IntervalsMedium

Sort intervals by start time — that guarantees any overlap can only happen between an interval and the one most recently merged. Then scan once: if the next interval starts before (or exactly when) the last merged interval ends, extend that interval's end; otherwise it's disjoint and starts a new group.

fun merge(intervals: Array<IntArray>): List<IntArray> {
    intervals.sortBy { it[0] }              // sort by start time
    val result = mutableListOf(intervals[0])
    for (i in 1 until intervals.size) {
        val last = result.last(); val cur = intervals[i]
        if (cur[0] <= last[1]) last[1] = maxOf(last[1], cur[1]) // overlap -> merge
        else result.add(cur)                                            // disjoint -> new group
    }
    return result
}
// O(n log n) time (sort dominates), O(n) space
P11-2Meeting Rooms II — minimum rooms neededMedium — Google Favorite

Sort meetings by start time, then track the end times of rooms currently in use in a min-heap. For each meeting, check the room that frees up earliest: if its end time is ≤ this meeting's start, that room is free — pop it and reuse it. Otherwise no existing room works, so the heap grows (a new room opens). The heap's final size is the peak number of rooms needed at once.

fun minMeetingRooms(intervals: Array<IntArray>): Int {
    val minHeap = PriorityQueue<Int>()               // end times of occupied rooms
    for (m in intervals.sortedBy { it[0] }) {
        if (minHeap.isNotEmpty() && minHeap.peek() <= m[0]) minHeap.poll() // reuse freed room
        minHeap.add(m[1])
    }
    return minHeap.size
}
// O(n log n) time, O(n) space
💡 Equivalent alternative: sort starts[] and ends[] separately and sweep both with two pointers — same O(n log n) time, O(1) extra space (excluding the sort).

★How to approach a coding problem at GoogleMust Know
  1. Clarify (2 min): Edge cases? Input constraints? Can I modify input? Return type?
  2. Example (2 min): Walk through 1-2 examples manually. Find the pattern.
  3. Brute force (2 min): State the O(n²) or obvious solution. "Naive approach is X."
  4. Optimize (5 min): Think about: sorting, two pointers, sliding window, hash map, DP, divide and conquer. State before coding.
  5. Code (15 min): Clean, readable code. Name variables well. Comments on non-obvious parts.
  6. Test (5 min): Walk through your code with the example. Test edge cases: empty, single element, all same.
  7. Complexity: State time and space complexity. Know how to derive it.
✓ Never code in silence. Think out loud. Interviewers want to see your process, not just the answer.
